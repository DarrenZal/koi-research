### Tool errors (paste raw)

Error querying graph via API: Graph API error (400):

### Verification evidence

**Reproduced errors for all 3 query types:**
- `list_keepers` → INVALID_QUERY_TYPE
- `list_messages` → INVALID_QUERY_TYPE
- `docs_mentioning` → INVALID_QUERY_TYPE

### Analysis: What is mismatched

**MCP Client Schema** (in `src/graph_tool.ts:68-76` and `src/validation.ts:50-70`) includes these query types that the **backend DOES NOT support**:
- `list_keepers`
- `list_messages`
- `docs_mentioning`
- `entities_in_doc`

**Backend API** supports these query types that are **NOT in the MCP schema**:
- `list_concepts`
- `explain_concept`
- `find_concept_for_query`
- `find_callers`
- `find_callees`
- `find_call_graph`

**Root cause:** The MCP server's tool schema was defined with query types that were planned but never implemented on the backend, OR the backend was updated and the MCP schema wasn't synced.

### Proposed Fix

**Option A (Recommended): Sync MCP schema to match backend**

**Files to change:**
1. `src/graph_tool.ts:68-76` - Remove unsupported types, add new ones
2. `src/validation.ts:50-70` - Same changes to Zod enum
3. `README.md:355-454` - Update documentation
4. `docs/API_REFERENCE.md:47` - Update API docs

**Specific changes:**
```typescript
// In src/graph_tool.ts and src/validation.ts
// REMOVE:
'list_keepers', 'list_messages', 'docs_mentioning', 'entities_in_doc'

// ADD:
'list_concepts', 'explain_concept', 'find_concept_for_query',
'find_callers', 'find_callees', 'find_call_graph'
```

**Option B: Implement missing query types in backend**
- Would require changes to the KOI Query API (koi-processor)
- More work but preserves original design intent

### Regression Test Idea

```typescript
// evals/schema_sync_test.ts
describe('MCP schema matches backend', () => {
  it('all MCP query_types should be accepted by backend', async () => {
    const mcpQueryTypes = GRAPH_TOOL.inputSchema.properties.query_type.enum;

    for (const queryType of mcpQueryTypes) {
      const response = await fetch(`${KOI_API_ENDPOINT}/graph`, {
        method: 'POST',
        body: JSON.stringify({ query_type: queryType, entity_name: 'test' })
      });

      // Should NOT return INVALID_QUERY_TYPE
      expect(response.status).not.toBe(400);
      const data = await response.json();
      expect(data.errors?.some(e => e.code === 'INVALID_QUERY_TYPE')).toBe(false);
    }
  });
});
```

This test could run in CI on every MCP server change to catch schema drift.
